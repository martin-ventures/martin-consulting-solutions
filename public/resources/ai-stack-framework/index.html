What is an AI stack? The six layers, and the lessons behind them

By Jeremy Martin, Martin Consulting Solutions · Published November 17, 2026 · 6 minute read

TL;DR: An AI stack is the set of files and habits around an AI assistant that lets each session start where the last one stopped. Ours has six layers: workspace, memory, handoffs, skills, principles, and guardrails. Each one exists because of a specific problem we hit. You can start this week with one folder, five notes, and a handoff habit.

What is an AI stack?

An AI stack is everything you keep around an AI assistant so that its work adds up over time. An assistant forgets everything when a conversation ends. The stack is the set of files and habits that gives the next session what the last one learned.

This page shows the six layers we run every day across client work, product work, and personal projects, the names we gave the working parts, and the problem that led to each one.

What are the six layers of an AI stack?

The layers build from the bottom up. Each one depends on the one before it.

#LayerWhat it isThe problem that led to it
1WorkspaceOne home for every file, in plain text, under version control, with a fixed folder map.Work was scattered across downloads, chats, and drives, so the assistant could not find what already existed.
2MemoryOne fact per file, plus an index the assistant reads at the start of every session: who we are, how we work, what we decided.Every session started from zero. We re-explained the same context and the assistant repeated the same mistakes.
3HandoffsA "next session" note for each project and one numbered list of open items, updated when a session closes.Long projects lost their place between sessions, and unfinished items disappeared.
4SkillsWritten instructions for work that repeats (e.g., a writing voice, a research method, a project kickoff interview), loaded only when that work comes up.Quality depended on how well we prompted that day. The same standards had to be restated every time.
5PrinciplesA short set of decision filters: what to build, in what order, how it should feel, and how it is put together.We built polished things that did not matter, and the assistant agreed with whatever we proposed.
6GuardrailsNamed actions that always need a person: deleting, sending, publishing, and anything touching credentials.An assistant that can act can also act wrongly. Speed without a gate is a risk.

What do we call each working part, and why does it exist?

We named the parts we reuse. A named practice gets reused; an unnamed one gets rediscovered.

NameLayerPurposeThe problem it solves
The Cairn2, 3The memory notes, their index, and the session-start and handoff habits (named for the stones that mark a trail).Sessions that start cold and re-earn the same ground.
The Mason2, 4The loop that maintains the Cairn: notice a lesson, place it, verify it, and prune what is not reused.Notes that pile up, go stale, and slow later sessions.
Grill Me4A skill: before a large build, the assistant asks ten or more questions in one batch, then writes a brief for sign-off.An hour of building on a wrong assumption.
The Triptych5Three independent tests for every meaningful decision: UHV, Polish, and Synergy (the next three rows).Leaning on one strength and neglecting the other two.
UHV5What to build at all: three questions that test whether something is worth building.Well-made features that did not matter.
Polish5How it should feel in the user's hands: controls that match instinct, confirmed actions, tested failure paths.The right idea, executed loosely enough to lose trust.
Synergy5How the person and the assistant work together: friction is a defect; refine, do not accumulate.The right thing, delivered painfully.
Substrate First5The ordering rule: small pieces that other work will stand on go ahead of larger features.Building the big thing first, then rebuilding it.
The Joinery5Nine rules for how the work is put together, so the next change stays cheap.Changes that break something somewhere else.
The Long Now5The time-horizon test: act as an owner, and separate one-way doors from two-way doors.Quick wins that cost more later.
The Front Door5, 6Use the official, authorized channel for every platform and data source.Workarounds that break and cost trust when they do.

What did we learn building it?

  • Capture in the moment. A lesson written at the end of a session has already lost its detail.
  • When memory and reality disagree, memory is wrong. Check a note against the current state before acting on it.
  • Name things. A named practice gets reused. An unnamed one gets rediscovered.

What tools do you need?

Three: an AI coding assistant that reads and writes files (we use Claude Code), a plain-text notes app, and Git. The layers matter more than the tools.

How do you start this week?

  1. Create one workspace folder and move one project's materials into it (e.g., for a career change: resume, profile text, course notes) to give the assistant one place to read.
  2. Write five memory notes: the goal, the background, the constraints, the writing voice, and the current plan, to remove the re-explaining.
  3. End every session with a handoff note: what was done, what is open, and what comes next, to make tomorrow start in minutes.
  4. Turn the first repeated task into a skill (e.g., a weekly status report) to hold one standard every time.
